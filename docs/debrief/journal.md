# デブリーフ journal

> `design-gate` / `debrief` セッションの記録。仕組みは [ADR 0014](../adr/0014-design-comprehension-gate-and-debrief.md)。
>
> 役割は 2 つ: (1) `debrief` skill の「前回以降」の**起点マーカー** (最新エントリの日付を使う)、(2) user の決定と学びの**累積ログ** (解説の深さ調整・振り返りに使う)。

## エントリ形式

新しいエントリを**このセクションの直後 (ファイル上部)** に追記する:

```markdown
## YYYY-MM-DD — {design-gate | debrief}

- **対象**: {扱った設計 / PR / ADR の一覧}
- **決定**: {ADR NNNN Accept / Reject / 修正、design-gate の承認・修正点}
- **学びメモ**: {user が曖昧だった箇所 → どう解説し直したか。次回の解説の深さ調整に使う}
- **特記**: {任意。そのセッション固有の記録 — 例: agent 側の失敗・見落としの分析。無ければ省略してよい}
- **持ち越し**: {未消化の項目・次回に回した判断。無ければ「なし」}
```

必須は **対象 / 決定 / 学びメモ / 持ち越し** の 4 項目。`特記` は任意項目で、省略しても他のエントリと同じ形として扱う。

## 2026-08-09 — design-gate (#4, hub-and-spoke の前提崩壊への対策)

- **対象**: [Issue #159](https://github.com/yomote/mind-inbox/issues/159) — ADR 0021 の「親が子セッションへ分配する」が実行環境で成立しないことが実測で判明。起案: [ADR 0028](../adr/0028-dispatch-packet-in-issue-and-session-start-preflight.md)
- **決定**: **ADR 0028 を Accept**。3 点:
  - **D1 分配は「起票パケットを Issue 本文に残す」で完了とする** — 押すボタンが親の API 呼び出しか user の 1 クリックかは実装詳細として分岐させ、前後 (パケット作成 / 子が PR・Issue に残す / 親がライブ集約) は環境によらず同一にする。ADR 0021 は supersede せず**条項 2 のみ置き換え** (窓口一元化の 1・3・4 は維持)
  - **D2 SessionStart フックで衝突を事前提示** — origin/main の sha と遅れ / **次に使える ADR 番号** / 直近 24h の更新ブランチ
  - **D3 ADR 採番衝突を CI で落とす** — README の手順を「origin/main の最大番号 +1」に改訂
- **学びメモ**: 理解確認は**不正解**。「ゲートが開いてもフックが要るのはなぜか」→「**フックが分配を代行してくれるから**」と回答。実際はフックは情報を提示するだけで起動には一切関与しない。正解は「**ゲートが開くと並行度が上がり、衝突機会が増える**」— ゲートは衝突問題の解決ではなく悪化要因。**この誤りは本日の他 2 件と同型**で、いずれも「ある結果を別の仕組みのおかげだと帰属する」形 (judge のスコアを現実と同一視 / CI の緑を動作の証拠と同一視)。**部品の責務境界を先に図で固定してから細部に入る**、を次回以降の既定にする
- **特記 (設計中にフック自身が実証した)**: 完成したフックを検証実行したところ、**その場で「main が進んでいてブランチが 1 コミット遅れ」を検出**した (PR #158 が 21 分前にマージされていた)。本日の重複作業と同じ状況を、規律ではなく機構が捕まえた最初の実例
- **判定 (同日中に決着)**: **permission では解けないことが実証された。** 同じ `.claude/settings.json` に登録した SessionStart フックが実際に発火した (= 設定は読まれている) 状態で `list_triggers` を再試行し、同じ `-32003` で失敗。設定が読まれていて通らない以上、permission 層ではなく**プラットフォーム側のゲートで確定**。効かないと分かった `permissions.allow` の行は誤読を生むので削除した。**D1 の「user が 1 クリック」は暫定回避策ではなく恒久的な運用形態**として確定
- **持ち越し**: needs-human は #90 / #92 の 2 件 (#156 は user が別セッションで解決・close 済み)

## 2026-08-08 — design-gate (#3, UX 自律改善ループ M2)

- **特記 (ゲートが実際に止めた 3 件)**: 設計を描く前に真実ソースを読んだ結果、**ADR 0022 の前提が 2 つ実装と食い違っていた**。①「評価 (自動)」は実際には runbook の手作業 3 ステップで、蓄積先の #127 も空 — **M2 のトリガーが読む先が存在しなかった**。②改変対象の `CHAT_SYSTEM_PROMPT` は v2 M1-3 で丸ごと置換される `workflow.py` の中にあり、毎朝の自動 PR と移行作業が同じファイルで衝突する。さらに③「到達経路を全部数える」(ADR 0017/0018 の手順) を実行したところ、素直に組むと **A/B が実環境のプロンプトを差し替える形になり、PO が実験台になる + ai-agent にプロンプト上書き口という扉が 1 枚増える** ことが判明 (#86 と同型)。rubric が会話文しか見ていない事実から、A/B を CI 上の ai-agent に閉じれば実環境に到達しないと分かった
- **学びメモ**: 理解確認 2 問とも設計と違う理解。**2 問の誤りは同じ 1 つの誤解に還元できた — 「judge (測定器) の出力を現実と同一視する」**。(1)「CI の A/B で勝った改案が実環境で効いていると何で分かるか」→「judge が高い点を付けたこと」と回答。実際は judge が採点したのは CI 内で生成された会話であり、実環境の会話を採点しているのは翌朝のプローブだけ。(2)「新旧に同一プロンプトを入れた対照実験で片方が 3 連勝したら何が分かるか」→「そのプロンプトが優秀」と回答。実際は**差が原理的に存在しない**ので、判定側が揺らぎを差として拾っている = judge が信用できない証拠。「体重計に何も乗せずに 3kg と出たら体重計を疑う」で解説し直した。**この誤解は journal 既知の「表層帰因」の一段深い形**で、今日の別テーマ (CI が緑 = 動く、ではない) とも同型 — 今後「測定器 / 現実」の区別は図で先に固定してから細部に入る。あわせて「対照実験 / CI の A/B / 翌朝のプローブ」が**それぞれ別の問いに答えていて、どれか 1 つでは結論が出ない**ことを表で示した
- **持ち越し**: 起票は完了 (#154 M1.5 / #155 プロンプト外出し + CI パス検査 — ともに epic #123 の sub-issue に接続 / #156 Routine 登録 = needs-human 3 件目)。**子セッションへの分配は不可だった** — claude-code-remote MCP サーバーが**丸ごと**承認ゲートの内側にあり、`create_session` / `create_trigger` はもちろん**読み取り専用の `list_environments` すら `-32003 requires approval`** で弾かれる (実測)。**#90 / #92 / #156 の滞留はすべてこの 1 つの原因**であり、個別事情ではない。分配できないため #154 / #155 は本セッションが実装した
- **特記 (並行セッションとの競合 — hub-and-spoke の失敗)**: 本セッションが design-gate と #154/#155 を進めている間に、**別セッションが保守性 Phase 3 (#133/#141/#142) を PR #152 で完遂・マージしていた**。着手前に `origin/main` を確認しなかったため、Phase 3 の前提として入れた frontend テスト基盤 (jsdom + testing-library) が丸ごと重複し、破棄することになった。さらに **ADR 番号が衝突** — main の PR #153 が `0026-cd-watchdog-routine` を先に採番していたため、本セッションの 0026 を **0027 へ改番**した (debrief #3 の「旧 0015 → 0019 改番」と同じ再発)。教訓: **長いセッションでは着手前と commit 前に `git fetch origin main` を挟む**。ADR の採番は「ローカルの最大値 +1」ではなく **origin/main の最大値 +1** で取る
- **学びメモ (追加)**: 一律 `environment: "jsdom"` にしたら `import.meta.url` が file: でなくなり、ソースを `readFileSync` で読む静的検査 2 ファイルが落ちた。main 側 (PR #152) は**ファイル先頭の `// @vitest-environment jsdom` docblock** で解決していた — 同じ問題に対して後から入った方が下手な解を選んでいた形。設定を広く変える前に、既存が同じ問題をどう解いているかを見る
