# デブリーフ journal

> `design-gate` / `debrief` セッションの記録。仕組みは [ADR 0014](../adr/0014-design-comprehension-gate-and-debrief.md)。
>
> 役割は 2 つ: (1) `debrief` skill の「前回以降」の**起点マーカー** (最新エントリの日付を使う)、(2) user の決定と学びの**累積ログ** (解説の深さ調整・振り返りに使う)。

## エントリ形式

新しいエントリを**このセクションの直後 (ファイル上部)** に追記する:

```markdown
## YYYY-MM-DD — {design-gate | debrief}

- **対象**: {扱った設計 / PR / ADR の一覧}
- **決定**: {ADR NNNN Accept / Reject / 修正、design-gate の承認・修正点}
- **学びメモ**: {user が曖昧だった箇所 → どう解説し直したか。次回の解説の深さ調整に使う}
- **特記**: {任意。そのセッション固有の記録 — 例: agent 側の失敗・見落としの分析。無ければ省略してよい}
- **持ち越し**: {未消化の項目・次回に回した判断。無ければ「なし」}
```

- **持ち越し**: 移行時に **clientId が一度だけ変わる可能性** (既存アプリに `uniqueName` を後付けできるかが未確認 — D9 第 1 段階で最初に確かめる)。持続層の bicep が検証されない穴 (明示的に先送り)。[PR #292](https://github.com/yomote/mind-inbox/pull/292) が `provision.sh` / `bootstrap-core.bicep` 等を占有しており main と衝突中 — 実装は当面これらのファイルを避け、config フェーズの適用は `deploy.yml` 側に置く

- **特記 (実バグの根治)**: PO が実環境で踏んだ「困りごと抽出がエラー」の真因は **api-version の共用**だった。`/chat` は chat completions (Semantic Kernel)、`/extract` は Responses API (Agent Framework) と**別のエンドポイント**を叩くのに同じバージョン指定を渡しており、後者で `400 API version not supported`。しかもライブラリは正しい既定 (`"preview"`) を持っており、**こちらが古い値で上書きしていた**。**実環境で抽出を通すテストが 1 つも無かった**ため、ずっと 0 件のまま気づかれていなかった (`problem.list` が 0 件だったのが裏付け)
- **特記 (エージェント側の失敗 — 決め打ち 6 連発)**: 原因に辿り着くまで**取得手段の修正を 5 回**要した。テーブル名 → 行の選び方 (`take` は最新ではない) → 対象の絞り込み (voicevox のログで埋まる) → 同居コンテナ (認証サイドカーで埋まる)。加えて Codex の能力を**ドキュメント 1 ページから一般化**して「PR でしか動かない」と誤断 (実際は cloud で実装も PR 作成もできる)。**形は毎回同じで「確かめずに決め打つ」**。これは同日 PO が指摘した「テストが仕様を勝手に発明する」と完全に同型で、**エージェント自身が同じ病気の実例を 6 回やった**
- **特記 (無人の仕組みが 4/4 沈黙)**: PR レビュー / cd-watchdog / ux-judge / maint-check がすべて機能していなかった。共通点は claude.ai 側にいて**実行履歴がリポジトリに残らない**こと + 「異常がなければ何も残さない」設計で**沈黙と正常が同じ見え方**になること。ADR 0008 の Negative Consequences (開発と枠を共有し超過時は拒否) が現実化した可能性が高いが**未確定** (#194 の確認待ち)。なお当初「枠を食い切ったから開発も止まった」と述べたが、**開発は止まっていない**ので言い過ぎであり訂正した
