# 0039. 対話画面を「キャラと話すと右で困りごとが形になる」構成にする — 読み取り専用プレビュー + 独自マスコット

- Status: Accepted (design-gate 2026-08-11 で PO 承認)
- Date: 2026-08-11
- Deciders: yomote (PO) / PM セッション
- Related: [ADR 0007](0007-problem-centric-two-layer-domain-model.md) (Problem 中心 2層) / [ADR 0030](0030-persistence-on-cosmos-db-single-store-behind-bff.md) (永続化は BFF の内側 — 本設計が安く済む根拠) / [ADR 0005](0005-mdx-ui-spec-as-truth.md) / [ADR 0024](0024-chat-streaming-via-sse-side-channel.md)

Technical Story: PO 発案 (2026-08-09 / #187)「左が対話、右に結果がだんだん形作られる」+ PO 実使用フィードバック (2026-08-10 / #229)「キャラクターが吹き出しで喋ってる感じにしてほしい。発話待ちの表現も欲しい」。#146 (stub 警告バナー) を同じ画面改修に同梱する。

## Context and Problem Statement

現状の相談画面はチャットバブルが積み上がるだけで、(1) AI が何を掴んだかがセッション中まったく見えず「困りごとを抽出」が一発勝負になっている、(2) 応答の主体が画面に存在せず、文字がぼんと出てから音声まで数秒の間が「壊れてる?」に近い体感になっている、(3) BFF が stub 応答のとき本物のふりをした偽応答が表示される。

## Decision Outcome (design-gate 2026-08-11 で PO が選択)

### D1 — 右ペインは「読み取り専用プレビュー」で作る

- BFF に **`consultation.preview` procedure を新設** (tRPC)。ai-agent の `/extract` を呼んで抽出 + グルーピング候補を計算するが、**Cosmos には一切書かない**。ai-agent 契約は不変 (計算のみ・書くのは BFF — ADR 0030 の構造をそのまま利用)
- 書き込み経路は従来の確定 `consultation.extract` **1 本のまま** (到達経路の点検済み)。preview が書かないことは L2 テストで固定する
- 右ペインのカードは**下書き (画面内のみ・保存しない)**。確定せずセッションを閉じれば消える。誤抽出が蓄積データを汚さない

### D2 — 更新は「ユーザー発話 2 往復ごと + 手動ボタン」

- 毎ターンは LLM 呼び出しが約 2 倍になり応答体感にも影響するため不採用。chat 応答への相乗り (1 呼び出し化) は契約大改造 (ADR 級) のため**将来の最適化**として残す
- 実行中の preview は重ねない (in-flight 1 本)。手動「今すぐ整理」ボタンを併設

### D3 — 確定導線は extractReview を維持

右ペインは予告編、確定ボタンは「この内容で確定」に文言変更。レビュー画面の検収機能は作り直さない。

### D4 — モバイルはタブ切替

「対話 / 整理中 N」の MUI Tabs。右ペイン更新時はバッジで通知。

### D5 — キャラクターは独自マスコット (声はずんだもんのまま)

- Mind Inbox のシンプルな SVG マスコットを新設。状態 3 種 (待機 / 音声準備中 / 発話中) で表情・アニメーションが変わり、AI 応答は吹き出しで表示
- ずんだもん立ち絵は立ち絵素材のライセンス確認が別途要るため不採用 (声の VOICEVOX 利用は既存のクレジット表記で継続)。抽象アバターは「キャラが喋ってる感」が薄く不採用
- **後から差し替え可能な Avatar 部品**として実装する (キャラ変更を安価に保つ)

### D6 — stub 警告バナーを同梱 (#146 / PO 決定済み 2026-08-08)

BFF の stub フォールバック応答に機械判別フラグ (`stubbed?: boolean` — 後方互換の optional) を載せ、フロントは警告バナー「AI サービス未接続 — スタブ応答を表示中」を表示。

## 到達経路の点検 (ADR 0018)

| 守るべき資源 | 経路 | 防ぎ方 |
| --- | --- | --- |
| LLM 呼び出し (課金・枠) | preview が新経路 | 2 往復ごと + in-flight 1 本 + 手動。1 セッション +2〜3 回程度 |
| Problem データ | 書けるのは確定 extract のみ | preview は BFF で書かない (L2 で固定)。下書きは揮発 |
| 公開面 | preview も既存 tRPC と同じ EasyAuth 401 の内側 | 新しい扉は増えない |

## 動作検証 (実装後に叩くもの — 先に決めた)

1. mock ブラウザ: 2 往復話す → 右ペインにカードが現れ、`problem.list` は増えていない → 確定して初めて増える
2. キャラ状態: AI 生成中 / 音声準備中 / 発話中で表現が変わる (`data-` 属性で機械検証 + 目視)
3. stub バナー: BFF stub 時に表示、実接続では非表示 (L2 + mock E2E)
4. スマホ幅: タブ切替で両ペインを操作できる (Playwright viewport)

## 実装フェーズ (依存順)

1. **Phase A**: #146 stub バナー (小・独立) + #229 キャラ・発話状態表現 (フロントのみ)
2. **Phase B**: #187 の preview procedure (BFF) + 右ペイン UI + タブ切替
3. UI 仕様は実装前に MDX へ (dialogue-session.mdx ほか / ADR 0005)

## 理解確認の記録

PO は「下書きは確定せず閉じると消える」「誤プレビューが出ても DB には何も起きていない」を正答 (2/2) — 設計の核 (揮発する下書き / 無垢な DB) の理解を確認済み。

## Positive Consequences

- 抽出が一発勝負でなくなり、「AI が何を掴んだか」が会話中に見える
- キャラクターの状態表現で TTS 待ちの数秒が「準備中」として意味を持つ
- stub 応答が本物のふりをしなくなる
- 下書き揮発 + 読み取り専用 preview により、機能全体が**可逆** (戻すコストが低い)

## Negative Consequences

- LLM 呼び出しが 1 セッションあたり数回増える (コスト微増 — 実測して閾値超過なら D2 を手動のみへ緩和)
- 下書きはセッションを跨いで残らない (意図した制約だが「さっきのカードが消えた」と感じる可能性 — UI で「確定していない下書きです」を明示)
- 独自マスコットのデザイン品質は初版では簡素 (差し替え可能性を優先)

## Considered Options

- 右ペイン更新: 毎ターン / **2 往復ごと + 手動 (採用)** / 手動のみ / chat 相乗り (将来)
- 途中経過: DB に書く / **揮発する下書き (採用)**
- キャラ: ずんだもん立ち絵 / **独自マスコット (採用)** / 抽象アバター
- モバイル: **タブ (採用)** / ボトムシート / 縦積み
