## 抽出結果レビュー

吐き出し（Dump = 1セッション全文）から抽出した Mention 群と、その自動グルーピング結果を提示する画面。
UC-01 の「段1 抽出 → 段2 グルーピング」の結果をユーザーに見せ、その場でトリアージできる。

## UI要素

- 「N件見つけた」見出し（新規 / 既存に追加の内訳）
- 各 Mention カード:
  - 新規 Problem / 既存に追加（グルーピング結果）バッジ。アイコンは `@mui/icons-material` を
    Chip の `icon` prop で表示する: 新規 = `FiberNew`、既存に追加 = `Repeat`
    （絵文字は使わない — [共通規約](./README.mdx)）
  - 主テーマチップ
  - `N回目` バッジ（`Repeat` アイコン + `N回目`。再出現の気づき / UC-03）・`再燃` バッジ（resolved/shelved から復活）
  - 困りごとの本文（`statement`）と元発話の引用（`excerpt`）
  - 感情チップ（`affect` の valence で色分け）
  - その場トリアージ: 新規に対する「これは違う（却下）」
- 「困りごと一覧へ」ボタン

## 状態

- 抽出0件: 「追跡する困りごとは見つかりませんでした。受け止めました。」（雑談・愚痴のみのケース。UC-01 代替フロー 2a）
- 抽出あり: Mention カード一覧
- **抽出失敗**: 本画面には遷移せず、対話セッションに留まったまま理由を Snackbar で伝える（#183 / 下記）

## 失敗したときの見せ方（Issue #183）

**「0 件だった」と「壊れた」を同じ見た目にしない。** 抽出が失敗したのに空の結果を返すと、画面は「追跡する困りごとは見つかりませんでした」と表示され、ユーザーは受け止められたと思って相談を終える。実際には何も記録されていない — 最も気づけない壊れ方なので、失敗は失敗として出す。

- 失敗時は `extractReview` へ遷移しない（対話セッションに留まり、会話は失われない）
- 理由に応じて文面を出し分ける。いずれも**次に何をすればいいか**まで書く:

| 種別               | 文面                                                                             |
| ------------------ | -------------------------------------------------------------------------------- |
| `session-missing`  | この相談の内容を取り出せませんでした。お手数ですが、もう一度お試しください。     |
| `llm-parse-failed` | 困りごとの整理に失敗しました。相談の内容は残っています。もう一度お試しください。 |
| `upstream-failed`  | 困りごとを抽出できませんでした。通信状況を確認して、もう一度お試しください。     |

- 種別の判断は API 層（`ExtractFailed.kind`）、文面はフロント（この仕様）が持つ。BFF は機械可読な token だけを返す
- スピナーは必ず止め、操作不能にしない（もう一度押せる）

## 抽出対象の会話をどこから取るか（Issue #183）

**会話全文は画面から渡す。** ai-agent のセッション履歴はプロセスメモリで、scale-to-zero・スケールアウト・リビジョン差し替えのいずれでも消えるため、それに依存すると「対話はできたのに抽出だけ失敗する」が起きる。会話の真実は画面が持っているので、抽出時に一緒に送る。

## 振る舞い

- 自動グルーピング（A案）: 承認ゲートなしで Problem は `open` 生成 / 既存へ付与済み。本画面は**事後トリアージ**の入口。
- 「却下」は誤抽出の新規 Problem を取り下げる（Mention は不変なので物理削除ではなくトリアージ操作）。

## 遷移

- 困りごと一覧へ -> `problemList`
- （入口）対話セッションの「この内容で確定」（下書きプレビュー無効環境では「困りごとを抽出」/ dialogue-session.mdx §5.8）-> `extractReview`

## 下書きプレビューとの関係（Issue #187 / ADR 0039 D3）

対話画面の右ペイン（dialogue-session.mdx §5.8）は本画面の**予告編**。プレビュー有効環境の「この内容で確定」は**表示中の下書きをそのまま永続化する**（`commitPreview` — 確定時に再抽出しない。契約は mockApi が真実で、BFF 側は #283 で同じ入出力に結線）ので、本画面に並ぶのは右ペインで見えていた内容そのもの。検収機能そのもの（カード表示・その場トリアージ・却下）は変えない。プレビュー無効環境（BFF 未結線の real）では従来どおり確定時に抽出を実行する。
