## 環境ステータスバナー

dev 環境は main への push ごとに自動デプロイされ（ADR 0013）、デプロイ直後の数分は
BFF の再起動で応答が不安定になる（#118）。その間にユーザー（PO）が触ると、原因の
分からないエラーに見える — 2026-08-10 の抽出エラー調査で実際に起きた。

このバナーは「今この環境、触って大丈夫?」を**触る場所そのもの（アプリ）に**出す。
状況ページや GitHub Actions を見に行く一手間を無くすことが存在理由。

## 表示仕様

ヘッダー（AppBar）直下・コンテンツの上に全幅で表示する。全画面共通。

| 状態 | 表示 | 判定 |
| --- | --- | --- |
| `deploying` | 🟡 warning「デプロイ進行中です — 数分間、応答が不安定になることがあります」 | deploy workflow に進行中（`status != completed`）の run がある |
| `broken` | 🔴 error「直近のデプロイ検証が失敗しています — 一部の機能が動かない可能性があります（状況ページ）」 | 直近の完了 run の `conclusion != success` |
| `ok` / `unknown` | 何も表示しない | 直近成功 / 判定不能・機能無効 |

- `deploying` と `broken` が同時に成立する場合（直前が赤 + いま再デプロイ中）は
  **`deploying` を優先**する。走っている deploy が直すかもしれない状況で赤を出すと
  「触るな」と読めてしまうため
- `broken` の「状況ページ」は <https://yomote.github.io/mind-inbox/status/> へのリンク
- 観測点: バナー要素に `data-env-status`（`deploying` / `broken`）を付与する

## データソースと更新

- 公開リポジトリの GitHub Actions API を**匿名で**読む:
  `GET https://api.github.com/repos/{VITE_ENV_STATUS_REPO}/actions/workflows/deploy.yml/runs?branch=main&per_page=5`
- 初回マウント時 + 120 秒ごとのポーリング + **タブがフォアグラウンドに戻った瞬間**に再取得
  （「ぱっと触るとき」に最新であることが目的なので visibilitychange が本命）
- 取得失敗（rate limit / ネットワーク断）は無視して直前の表示を保つ。バナー自身の障害で
  アプリを巻き込まない

## 有効化の条件

- ビルド時変数 `VITE_ENV_STATUS_REPO`（`owner/repo`）が焼き込まれている場合のみ動く。
  CI デプロイでは `deploy-frontend.sh` が `GITHUB_REPOSITORY` から自動設定する
- 未設定（ローカル dev / mock デモ / テスト / E2E）では **fetch を一切しない**。
  外部サービス無しで動く特性（stub fallback）を壊さないため
